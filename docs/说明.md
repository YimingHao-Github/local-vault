## 数据与实现

### 文件位置与内容

默认 `vault.lvault` 与实际安装后的 `LocalVault.exe` 位于同一目录；冻结程序以可执行文件所在目录确定位置，源码模式以工程根目录确定，不依赖当前工作目录。设置界面显示实际文件路径，可选择新文件夹自动迁移并记住位置。普通启动优先使用已记住的位置，已知保险库缺失或不可访问时明确报错，提供选择文件夹和重试入口，不重新初始化空库。

位置设置位于 `%LOCALAPPDATA%\LocalVault\location.json`，只包含目录、是否预期已有保险库及未完成迁移的恢复记录，不包含正文、主密码或密钥。未设置位置时发现旧默认目录的 `vault.lvault`，会自动迁移到安装目录；目标已有库时拒绝覆盖或合并。旧目录的导出、备份、历史副本和无关文件均不处理。显式 `--data-dir` 会完全隔离普通配置与旧库发现，仅用于开发和虚构测试。

| 文件 | 用途 |
| --- | --- |
| `vault.lvault` | 当前保险库 |
| `vault.lvault.bak`、`vault.lvault.before-restore-*.bak` | 旧版可能遗留的历史副本；新版不生成、更新或删除 |
| `vault.lvault.lock` | 写入期间的系统文件锁 |
| `application.lock` | 同一数据目录的窗口排他锁 |
| `location.json` | 用户记住的保存位置及迁移恢复记录，位于旧默认目录 |
| `location-session.lock`、`location.json.lock` | 位置会话排他锁及设置写入锁，位于配置目录 |

锁文件不保存正文或密码；程序退出或崩溃后，系统释放文件锁，空锁文件可能继续存在。覆盖导出或手动备份文件时可能产生同名 `.lock`，不再产生 `.bak`。

保险库、导出和备份中的标题、条目唯一编号为明文；条目数量、文件大小和闲置锁定设置也可以直接看到。正文加密，主密码不直接保存。条目编号为 UUID，新增时分配，编辑和普通导出时保留。

### 密码派生与加密

使用 `cryptography` 提供的 scrypt 和 AES-256-GCM：

- 新设置的密码为 16～1024 个字符，按 UTF-8 编码；拒绝全空白、常见弱口令及简单重复、顺序模式，允许长口令，不强制字符组合。密码不裁剪、不改变大小写、不截断，不发送到外部服务。
- 新建、修改主密码和新导出使用 scrypt `n=131072`、`r=8`、`p=1`，派生 32 字节密钥。读取仅接受这一配置或旧版 `n=32768`、`r=8`、`p=1`，不执行文件任意指定的消耗参数。
- 读取旧文件仍接受旧版 8～1024 字符密码。普通编辑不会升级旧库，修改主密码才重新派生和加密；旧版 `1.0.0` 不支持加强参数，不能读取新库、新导出或新库的完整备份。两台电脑交换新导出前均需升级。
- 新保险库、修改主密码及每次导出使用新生成的 16 字节盐值。
- 每次加密生成 12 字节随机数，认证标签为 16 字节。
- 正文的附加认证数据包含条目编号与标题。
- 文件目录另有认证标签，覆盖文件类型、版本、派生参数、密码验证字段、条目目录及保险库设置。

本机 Windows 11、Python 3.12.6、cryptography 50.0.2，使用虚构密码分别测量两组参数各 5 次：旧参数中位耗时 53.095 毫秒（52.677～54.238），新参数 216.823 毫秒（215.066～217.789）。scrypt 主要算法内存约为 32 MiB 与 128 MiB，进程仍有额外开销。测量报告为 `build/current-update-kdf-timing.json`；其他电脑耗时可能不同，字符长度和算法名称不保证不可破解。

解锁时检查密码验证字段、目录认证和每条正文的认证及编码。正文、密码验证、目录认证和内存草稿使用不同的附加认证数据域。

### 文件格式

文件为 UTF-8 JSON，顶层字段如下：

| 字段 | 内容 |
| --- | --- |
| `format` | 保险库为 `local-vault`，导出为 `local-vault-export` |
| `version` | 数据格式版本，目前为整数 `1` |
| `kdf` | `name`、`salt`、`n`、`r`、`p` |
| `check` | 密码验证字段的 `nonce`、`ciphertext` |
| `entries` | 每条包含 `id`、`title`、`nonce`、`ciphertext` |
| `authentication` | 目录认证的 `nonce`、`ciphertext` |
| `idle_minutes` | 仅保险库包含，整数 0～120，0 表示关闭自动锁定 |

盐值、随机数和密文采用规范 Base64 编码。目录认证使用除 `authentication` 外的内容，经键名排序、紧凑分隔符和保留中文字符的规范 JSON 编码后计算。

读取时校验文件类型、版本、字段、编号、编码和派生参数，拒绝重复 JSON 字段或条目编号。限制为：单文件 128 MiB、单条正文 8 MiB、10000 个条目、标题 200 个字符。标题不能全为空白；标题首尾空格和正文的大小写、空格、制表符、换行均按原样保存。正文可以为空。

### 保存、备份与恢复

保存时在同目录创建加密临时文件，写完后刷新到磁盘，再通过 `os.replace` 替换目标；文件提交成功后才更新内存状态。正常完成或写入失败时清理本次临时文件，不自动保存历史副本。进程被强行终止或系统断电可能留下加密临时文件，不保证对旧磁盘内容进行安全擦除。

系统文件锁协调写入，并通过原文件的 SHA-256 指纹检查文件是否被其他程序修改。同一数据目录只允许一个应用窗口。

迁移不重新加密：持有位置配置会话锁、源和目标目录实例锁以及保险库写锁，检查源指纹，在目标目录写入并刷新加密临时文件，以不覆盖现有文件的方式提交，再逐字节验证。记录可恢复的目标位置及源信息后，再次核对两个文件，最后删除原文件并切换当前会话。复制、验证、配置保存或原文件删除失败时保留原库和原会话位置，清理本次仍未改动的目标副本；中断记录在重启时核对文件身份和摘要，删除源之前的中断退回原位置，源已移除的已提交迁移继续使用目标。清理记录失败时，后续保存先重试清理，避免写入使迁移恢复依据失效。

选择目录取消不触发未保存编辑处理；选定目录后、迁移前沿用保存、放弃或取消流程。选择期间正文遮蔽、闲置超时取消操作，迁移写入沿用现有不可中断提交保护。新位置的实例锁持续持有到退出，旧版仍运行或目标目录有实例时拒绝迁移。相同目录只返回、不重复搬动，已有目标库即使字节相同或为硬链接也不覆盖。

完整备份复制保险库文件。恢复先校验备份，再替换当前保险库，恢复后使用备份中的主密码和设置。启动时若主文件格式损坏，可以进入恢复流程。

恢复写入保留来源，包括恢复旧版遗留的 `.bak`，不再额外另存恢复前主文件。最终替换失败时，主文件保持原字节，来源备份仍可解密并用于重试；取消恢复、密码错误或备份校验失败时不提交写入。

修改主密码会重新生成盐值、密钥并以加强参数加密正文。已有手动备份、导出和旧版遗留副本继续使用原密码，新版不扫描或清理它们。删除仅作用于当前保险库，其他副本可能保留原内容。

### 导出与合并

导出使用独立密码、新盐值和新密钥，保留选中条目的编号、明文标题和加密正文。另一台电脑解密导入后，用目标电脑的保险库的主密码重新加密。

导入先校验文件和全部正文，再生成预览；规则见 [使用手册](../README.md#导出与另一台电脑导入)。预览在本地修改、重新解锁、生成新预览或成功提交后失效。整批合并只进行一次保存，部分导入保留未包含的本地条目。

预览分类以导入前的内容为依据，暂判重复不代表提交时必然跳过。同一编号的内容冲突仍需明确选择，导入文件内较早出现的同文条目不会掩盖这类冲突。提交先统一移除明确选择覆盖的旧版本，保留其余本地条目，再处理覆盖版本与追加候选，按完整标题和正文精确去重。暂判重复项若在覆盖后的结果中不再存在，就补入；大小写、空格和换行均参与比较，导入顺序不造成旧内容漏导入。没有参与覆盖的本地既有重复条目保留，不借导入清理本地数据。

### 锁定与草稿

启动时保持锁定，解锁后可以连续查看和编辑。锁定清空正文控件和撤销记录，并丢弃当前密钥。对话框打开不会无限暂停闲置计时；未完成的导入比较在锁定后失效，不能提交旧预览。短暂不可中断的写入完成后再检查锁定。

解锁期间使用同一 Tk 事件循环内的中文密码、设置、导入比较、文件选择和消息确认窗口；实际键鼠操作刷新闲置时间，仅打开窗口不刷新。超时关闭这些窗口、遮蔽正文并使待处理操作的解锁代次失效。文件选择前会暂时遮蔽主窗口正文；正常取消或选择后在仍有效的解锁状态下恢复编辑器。启动时损坏库的恢复入口尚未解锁，没有可显示的正文，可使用系统文件选择窗口。

自动锁定前的未保存编辑加密暂存在内存，解锁后恢复，保存前不写入保险库。草稿封装上限为 128 MiB，可以暂存超过普通保存限制的编辑内容；恢复后仍需满足正常限制才能保存。

草稿加密异常时仍立即清空正文控件、撤销记录并丢弃保险库密钥；编辑保留为不可从界面访问的内存条目。提示明确说明“尚未成功加密”，要求重新输入主密码后保存或放弃，不能把这一状态描述成成功加密的草稿。关闭仍可保存、放弃或取消，失败的保存保留草稿以便重试。异常草稿尚在明文内存中，意外退出会丢失，不增加磁盘副本。

设置正文控件时先加载文本，再清空撤销记录，以加载完成后的正文建立撤销基线。打开或切换条目、解锁恢复草稿后，直接撤销不会清空原文，也不会带入其他条目的撤销记录；后续用户编辑仍可撤销和重做。

关闭窗口时若有锁定草稿，先提供保存并退出、放弃并退出和取消退出三种选择。保存先解锁，保存成功后才退出；放弃直接丢弃草稿，无需解锁且不修改保险库；取消保留加密草稿和锁定状态。取消解锁、密码错误或保存失败时不退出也不丢弃未保存修改，允许重试或重新选择。未锁定时沿用保存、放弃和取消流程。

锁定用于停止从界面读取正文，Python 与系统内存管理不能保证擦除所有明文副本。手动复制由系统剪贴板管理。加密认证可以发现文件改动，但不能识别整个文件被替换为较早的有效版本。忘记密码且没有可解锁备份时，无法恢复正文。

## 开发与发布

运行、测试和构建命令见 [README](../README.md#源码运行与构建)。依赖版本固定在 `requirements*.txt`，构建需要网络，安装后使用离线。

- `--data-dir 路径`：指定独立数据目录。
- `--smoke-test --report 路径`：使用临时虚构数据进行加密与界面组件自测。
- `--version --report 路径`：查询版本。
- `tests/fixtures/fake_entries.json`：虚构样例，不预装到正式保险库。

构建使用 PyInstaller 和 Inno Setup，输出到 `dist`，安装包包含 README、GOAL 和本说明。推送 `v*` 标签后，GitHub Actions 验证版本、运行测试、构建并验证安装，再发布安装包与校验和。发布正文从本文件的版本说明标记中提取。构建默认跳过会改动剪贴板的一项测试，专用环境可以显式使用 `-IncludeClipboardTest`。

`scripts/test-installation.ps1` 采用独立应用编号、安装目录和模拟用户资料，从 `v1.0.0` 的真实源码构建旧程序，验证旧版到当前版本升级、正常启动、旧文件原密码读取和卸载保留虚构数据。测试安装不会注册或卸载正式应用。`scripts/update-installed.ps1 -SetupPath 安装包路径` 校验摘要后沿用正式安装位置覆盖更新，再用虚构数据查询实际版本并自检；运行前需要保存编辑并关闭应用，不强制终止进程，也不读取真实保险库。
