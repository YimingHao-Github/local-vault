# 本地密匣的数据与安全说明

本文对应应用版本 `1.0.0`、数据格式版本 `1`，以当前源码 `local_vault/core.py` 的实现为准。

## 数据放在哪里

默认数据目录为 `%LOCALAPPDATA%\LocalVault`，当前保险库为 `vault.lvault`。程序文件与用户数据分开放置，更新程序后继续读取原数据目录。开发与虚构测试可以用 `--data-dir` 指定其他目录。

该目录还会有：

- `vault.lvault.bak`：最近一次成功保存之前的完整保险库密文。
- `vault.lvault.lock`：保存期间使用的系统文件锁，不保存条目或密码。
- `application.lock`：同一数据目录的窗口排他锁，不保存条目或密码。

系统在程序退出或崩溃后释放文件锁。锁文件可能仍留在目录中，其存在本身不表示程序还在运行。

导出与手动备份的目标文件也使用同目录 `.lock` 文件；覆盖已有目标时，会把旧目标内容保留为同名 `.bak`。这些额外备份仍属于私人文件，应一并妥善保管。

保险库、加密导出和加密备份属于私人数据，不能加入公开源码仓库。仓库中的示例与验收测试只包含明确标记的虚构内容。程序正常使用时不需要联网。

## 哪些内容可以被直接看到

保险库文件、导出文件和备份文件中的标题及条目唯一编号均为明文。条目数量、文件大小和保险库闲置锁定设置也可以被看到。主界面在未解锁时显示标题列表，但不显示正文。

正文使用带完整性验证的加密保存，不在文件中存储正文原文。主密码不直接保存到文件。建议不要把密码、密钥等敏感内容写进标题。

内部编号为规范形式的 UUID。新增条目分配新编号，编辑和普通导出保留编号；合并时选择“两份都保留”会为导入副本分配新编号。编号不在普通编辑界面显示。

## 密码派生与加密

密码交由成熟密码学库 `cryptography` 处理。密码按 UTF-8 编码，使用 scrypt 派生 32 字节密钥。格式版本 `1` 的参数固定为 `n=32768`、`r=8`、`p=1`；每个新保险库或导出文件使用随机生成的 16 字节盐值。主密码及导出密码允许 8 至 1024 个字符。

正文使用 AES-256-GCM 加密，每次加密生成随机的 12 字节随机数，并包含 16 字节认证标签。条目编号与标题作为正文的附加认证数据，不能把某一条的密文移到另一条中使用。

文件还具有覆盖整个目录的 GCM 认证标签。它认证文件类型、版本、密码派生参数、密码验证字段、全部条目编号、标题和密文，以及保险库的闲置锁定设置。修改标题、替换密文或删掉目录中的条目后，文件无法正常解锁、导入或恢复。

解锁时会检查密码验证字段、整体目录认证，以及每一条正文的认证和文本编码。错误密码或损坏文件不会被当成一个空保险库重新初始化。

## 文件格式

文件使用 UTF-8 JSON，格式版本 `1` 的顶层字段如下：

| 字段 | 含义 |
| --- | --- |
| `format` | 保险库为 `local-vault`，导出为 `local-vault-export` |
| `version` | 数据格式版本，目前固定为整数 `1` |
| `kdf` | `name`、`salt`、`n`、`r`、`p`，记录固定 scrypt 参数和盐值 |
| `check` | `nonce` 与 `ciphertext`，用于加密的密码验证字段 |
| `entries` | 条目数组，每条包含 `id`、`title`、`nonce`、`ciphertext` |
| `authentication` | `nonce` 与 `ciphertext`，认证整个文件目录 |
| `idle_minutes` | 仅保险库包含，整数 `0` 至 `120`，`0` 表示关闭自动锁定 |

盐值、随机数和密文使用规范的 Base64 编码。目录认证以除 `authentication` 以外的顶层内容为输入，使用键名排序、紧凑分隔符和保留中文字符的规范 JSON 编码。正文、密码验证、目录认证和内存草稿使用不同的附加认证数据域。

读取时拒绝重复 JSON 字段、未知字段、重复条目编号、不规范的编号或编码，以及不支持的格式和密码派生参数。单文件上限为 128 MiB，单条正文按 UTF-8 编码后上限为 8 MiB，条目上限为 10000，标题上限为 200 个字符。标题不得只有空白；标题的首尾空格仍按原样保存。正文允许空串，保留大小写、空格、制表符以及原有换行，不主动整理文本。

## 保存、备份和恢复

保存先在目标文件所在目录创建临时文件，写完后刷新并同步到磁盘，再使用 `os.replace` 替换目标文件。原保险库在替换前保存为 `.bak`。正文编辑、删除、修改主密码和导入合并都先生成完整候选数据；只有文件替换成功后才更新内存状态。普通写入失败时保留原保险库和原内存数据。

同一目录使用系统文件锁协调应用的写入，并对原文件字节计算 SHA-256 指纹。当发现文件自打开后已被其他实例修改时，拒绝用旧状态覆盖新文件，要求重新打开。文件系统、硬件突然故障以及不遵循本应用文件锁的外部程序仍有其各自的限制；请保留独立备份。

“完整加密备份”复制整个保险库，锁定状态下也可以备份，恢复需要备份创建时的主密码。“恢复”会先完整校验备份再替换当前保险库，旧保险库会进入 `.bak`；恢复后使用备份中的主密码和锁定设置。恢复是全部替换，与追加导入不同。

若启动时发现当前保险库格式损坏，可以进入专用恢复流程。此流程只记录原文件指纹，禁止创建空保险库覆盖，也禁止正常读取或编辑；只有完整校验成功的备份才允许替换原文件。取消、密码错误或备份损坏时，原文件保持不变。

修改主密码会重新生成盐值和密钥，并重新加密所有已有正文。修改前的自动备份和手动备份仍使用旧主密码；修改主密码不会修改已经导出的文件。删除只作用于当前保险库，历史备份可能保留删除前的密文，并非磁盘安全擦除。

## 导出与合并

加密导出使用本次设置的导出密码、新盐值和新密钥，包含所选条目的原编号、明文标题和加密正文。文件不绑定电脑或 Windows 账户，导出不修改本地条目。另一台电脑使用导出密码读入，再用其当前保险库的主密码重新加密保存。

导入先校验整个文件和全部正文，再生成只读预览。取消预览不会修改本地保险库。合并按以下规则执行：

- 标题与正文逐字相同，归为重复，只保留一份；文件内部的完全相同内容也去重。
- 编号不存在、标题也不重复，归为新增。
- 编号相同但标题或正文不同，必须明确选择“保留本地”“采用导入内容”或“两份都保留”。
- 编号不同、标题相同、正文不同，提示可能重复，可选择保留本地或两份都保留；默认两份都保留。

完整内容去重优先于编号冲突判定。选择保留副本后再次导入完全相同的内容，仍只保留已有的一份。导入文件中没有的本地条目继续保留，第一版不传播删除操作。

预览后本地数据有修改、锁定后重新解锁、创建了新预览，或预览已成功提交，原预览即失效。一次合并只进行一次整批保存，保存失败不会留下已导入一半的数据。

## 锁定与内存边界

程序启动后保持锁定。首次解锁后，本次解锁期间可以连续查看、编辑条目；手动锁定和闲置自动锁定会清空正文编辑框与撤销记录，并丢弃当前密钥。闲置设置仅在解锁后修改，默认 5 分钟。

自动锁定前尚未保存的编辑使用当前密钥加密后仅暂存在内存中，解锁后恢复，不会自动写入保险库。草稿不写入磁盘；意外终止程序后草稿消失。正常关闭时会要求处理未保存修改。

内存草稿允许暂时超过正常保存的标题或正文限制，总封装上限为 128 MiB。恢复草稿后仍须满足普通保存限制才能保存到保险库。

Python、桌面文本组件和系统内存管理不能保证所有曾出现的明文副本已被物理擦除。锁定主要防止继续从界面读取正文，不替代设备与 Windows 账户保护。手动复制的内容交给系统剪贴板管理，本应用不会自动清除剪贴板。

密码没有找回入口。忘记保险库密码且没有可解锁的备份时，无法恢复正文。认证可以发现未授权改动，但不能识别外部人员将整个文件替换成一个较早的、仍然有效的加密版本。
